# MOEMS Division E and M Exam Percentile Report Generator

Tools for computing exam percentiles and generating per-student PDF reports. Each report shows a student's score on a 5-question exam and their percentile rank relative to one or more comparison populations (team, all participants, grade levels, etc.).

This software was specifically written to support generating reports for the kids I coach
in MOEMS Division E and Division M in our local school district.

Each year, there are 5 contests, and each contest consists of 5 questions. Ultimately, these 
scores are entered online (MOEMS has a portal for the school point of contact where this can 
be done). MOEMs will give you a web page that tells you the following:

- What percentage of your students got all 5 answers correct, 4 correct, ..., 0 correct.
- Same information for all schools nationwide
- Same information for each grade level (e.g., 4, 5, 6).
- Population sizes (your school, all schools, all 6th grade, all 5th grade...)

This is enough information to generate a report per student that lets them not only know
their score for the contest, but their percentile ranking relative to the team they are on,
the nation, all 4th graders nationwide, all 5th graders nationwide, etc.. This can be handed
out when contests are returned to the students, helping them to better understand how they
performed. This can have subtle effects. Consider a child that got 1 out of 5, for example.
If they see that relative to their grade most other kids got a 1 as well, this context can
help them to better understand that the problem was actually quite hard, and to accept the
lower score without feeling overly discouraged. Hopefully this tool makes it easier for these
sort of discussions to happen between kids and their parents, or with coaches. I encourage
looking at the data generated by MOEMS and using this tool to package it in a way that is
meaningful to the individual participants.

As far as math goes, the basic equation for computing percentiles is the following:

For a student who scored Y (0–5):

percentile = (% below Y) + 0.5 × (% exactly at Y)

(see the function percentile_rank for details on how this is implemented in code)

One inconvenience at the moment is the data up on the MOEMs site is nice for viewing, but
hard for ingestion into a tool like this. What is needed is CSV data that can be transformed
into the yaml files this code uses to record the various contest data. I am planning to 
speak with MOEMS about this, and if they agree and implement data export, I will patch this
code with tools that map whatever they come up with to the yamls these tools need. For now, 
you have to hand edit the yamls copying the data from the web page (or typing it in by hand
as I end up doing). if you wait until the end of the season to do it, takes an hour or so 
for all 5 contests, depending on how many team members there are.

If you generate these reports after each contest, expect 10 or 15 minutes max to do the
data prep and generate reports.

## Programs

| Program | Purpose |
|---------|---------|
| `exam_percentile.py` | Interactive calculator — prompts for inputs and prints percentiles to the terminal |
| `exam_percentile_report.py` | Generates PDF reports for one contest from YAML input files |
| `exam_batch_reports.py` | Generates PDF reports for one contest or an entire season from a season YAML file |

## Installation

Requires Python 3.9+.

```bash
cd "/path/to/cursor projects"
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

On macOS, if matplotlib warns about its config directory, set:

```bash
export MPLCONFIGDIR="$(pwd)/.matplotlib"
```

## Quick start

Generate all reports for the included sample season (5 contests × 17 students = 85 PDFs):

```bash
.venv/bin/python exam_batch_reports.py sample_data/2025-2026/season.yaml
```

Reports are written to `sample_data/2025-2026/reports/contest_01/` through `contest_05/`.

## YAML file formats

### Populations file

Describes the comparison groups for a contest. You can include any number of populations.

```yaml
populations:
  - label: my team
    size: 17
    score_percentages: [10, 22, 28, 20, 14, 6]

  - label: all
    size: 1000
    score_percentages: [5, 10, 17, 24, 24, 20]

  - label: 6th grade
    size: 400
    score_percentages: [7, 12, 19, 24, 23, 15]
```

**Fields:**

- `label` — display name for the population (e.g. `my team`, `all`, `6th grade`)
- `size` — number of students in that population
- `score_percentages` — list of 6 percentages that must sum to 100:
  - index 0 = % who scored **5** correct
  - index 1 = % who scored **4** correct
  - index 2 = % who scored **3** correct
  - index 3 = % who scored **2** correct
  - index 4 = % who scored **1** correct
  - index 5 = % who scored **0** correct

When a population is labeled `my team`, the `--team-name` value (or the team name from a season file) replaces that label on the PDF.

### Students file

Lists team members and their scores for one contest.

```yaml
students:
  - name: Maya Chen
    score: 4

  - name: Jordan Brooks
    score: 3
```

**Fields:**

- `name` — student name (used on the report and in the output filename)
- `score` — number of questions answered correctly (0–5)

Each student receives their own PDF. Other students' scores are never shown.

### Season file

Used by the batch runner to define team metadata and a list of contests.

```yaml
team_name: Riverside Math Team
season: "2025 - 2026"
contests:
  - number: 1
    populations: contests/contest_01/populations.yaml
    students: contests/contest_01/students.yaml

  - number: 2
    populations: contests/contest_02/populations.yaml
    students: contests/contest_02/students.yaml
```

**Fields:**

- `team_name` — shown on every report; replaces the `my team` population label
- `season` — season label shown on every report (e.g. `"2025 - 2026"`)
- `contests` — list of contests, each with:
  - `number` — contest number (must be unique within the season)
  - `populations` — path to the populations YAML for that contest
  - `students` — path to the students YAML for that contest

Paths in the season file are relative to the season file's directory.

## Generating reports

### Batch mode — full season

Generate reports for every contest in a season:

```bash
.venv/bin/python exam_batch_reports.py sample_data/2025-2026/season.yaml
```

Output layout:

```
sample_data/2025-2026/reports/
  contest_01/
    Maya_Chen_contest_01_report.pdf
    Jordan_Brooks_contest_01_report.pdf
    ...
  contest_02/
    ...
```

### Batch mode — single contest

Generate reports for one contest only:

```bash
.venv/bin/python exam_batch_reports.py sample_data/2025-2026/season.yaml --contest 3
```

### Batch mode — custom output directory

```bash
.venv/bin/python exam_batch_reports.py sample_data/2025-2026/season.yaml \
  -o /path/to/output
```

Contest subfolders (`contest_01/`, `contest_02/`, etc.) are created inside the output directory.

### Single contest mode

Generate reports directly from a populations file and a students file, without a season file:

```bash
.venv/bin/python exam_percentile_report.py \
  sample_data/2025-2026/contests/contest_03/populations.yaml \
  sample_data/2025-2026/contests/contest_03/students.yaml \
  --team-name "Riverside Math Team" \
  --season "2025 - 2026" \
  --contest-number 3 \
  -o sample_data/2025-2026/reports/contest_03
```

**Options:**

| Flag | Description |
|------|-------------|
| `-o`, `--output-dir` | Output directory (default: `reports`) |
| `--team-name` | Team name on reports; replaces `my team` label |
| `--season` | Season label (e.g. `"2025 - 2026"`) |
| `--contest-number` | Contest number; included in report title and filename |

If metadata flags are omitted, reports still generate but use generic headings and filenames without a contest number.

### Interactive calculator

For a quick percentile check without generating PDFs:

```bash
.venv/bin/python exam_percentile.py
```

The program prompts for population sizes, score breakdowns (0–5 correct) for populations A and B, and the student's score, then prints percentile ranks.

## Report contents

Each PDF contains:

1. **Summary page**
   - Team name, season, and contest number
   - Student name and score (X out of 5)
   - Horizontal bar chart of percentile rank vs. each comparison population

2. **Distribution page(s)**
   - For each population: score distribution bars, cumulative curve, and a marker at the student's score
   - Up to three populations per page

Output filenames include the contest number when one is specified:

```
Maya_Chen_contest_03_report.pdf
```

## Percentile calculation

All programs use the same **midrank** formula:

```
percentile = (% scoring below student) + 0.5 × (% scoring the same)
```

Example: if 30% scored below 3 and 25% scored exactly 3, the percentile is 30 + 0.5 × 25 = **42.5th**.

A 75th percentile means roughly 75% of students in that population scored at or below the student's result.
